Environment-Mediated GOAP for Dynamic Triage Transport

This page summarizes a Unity-based agent simulation comparing a proposed environment-mediated GOAP replanner against three baseline controllers under compressed triage-arrival workloads.

Overview Dataset Experimental Design Architecture Results Distributions Tables

Overview

The experiment tests whether environment-mediated online replanning can preserve fast access for critical patients while maintaining overall throughput under dense, conflict-prone patient flow. The proposed controller does not assign each patient a separate private world model. Instead, it updates shared environmental accessibility and resource-level filters; patient priority, queue position, and current state then determine whether the same corridor or resource admits or rejects a given agent.

300 Scheduled patients per run
67 Critical patients, 22.3% of the workload
30 Assessment cubicles, split across two wings
2-5 min Triage/contact time bound used in the simulation

Dataset Construction

Dataset note. The results page uses a MIMIC-IV-ED demo-informed synthetic trace. The public demo subset is suitable for reproducing the shape of emergency-department records, but it is too sparse to represent a complete high-load operational day directly. Therefore, arrivals and patient metadata were resampled and compressed into controlled stress-test schedules. The evaluation is a transport-control experiment, not a clinical validation study.

MIMIC-IV-ED demo Used as the source style for ED stay metadata and trace-inspired arrivals
Trace-inspired Arrivals are compressed into load multipliers: 2.00, 1.50, 1.25, 1.00
Protocol bounds 5 min maximum triage contact and 15 min target access window are reported separately

Experimental Design

Each run schedules the same 300-patient workload and stops only after every scheduled patient has completed assessment and reached home. The load multiplier controls arrival compression: lower values represent denser arrivals. All controllers are tested on the same transport map, cubicle capacity, patient mix, and service-time settings.

FSM / Reactive Controller

A local one-goal reactive baseline. Agents follow fixed state transitions and do not perform multi-step online planning.

Priority Queue Dispatcher

A centralized priority assignment baseline. Patient order is resolved through a queue before resource acquisition.

Decision Table Controller

A rule-based controller using priority, resource availability, conflict, and buffer conditions without full GOAP search.

Proposed Environment-Mediated GOAP

Shared environment changes trigger rollback and online replanning. Conditional resources filter access by priority, queue state, occupancy, and availability.

Architecture

The mediator observes queue and resource events, updates shared world-state counters, and changes resource accessibility. Agents execute GOAP plans against that environment; when a target becomes invalid, action rollback releases reservations before a new plan is requested.

Results Summary

The proposed controller is load-dependent. At lighter arrival densities it introduces extra waiting for normal patients because the environment preserves critical access and performs more world-state changes. At the densest workload, those same mechanisms reduce critical access delay and slightly improve overall completion relative to the strongest baseline.

50.81 min Dense-load completion time for proposed GOAP, marginally ahead of the best baseline at 50.83 min
1.35 min Dense-load critical mean time to assessment for proposed GOAP
40.00% Dense-load all-patient 15 min access breach rate, lower than all baselines in that setting

Distribution Plots

Boxplots and dense-load histograms make the trade-off more visible than mean-only curves. The proposed method has overhead in low and medium demand, but the dense workload shows a tighter critical access distribution and reduced tail delay for normal patients compared with the average baseline behavior.
